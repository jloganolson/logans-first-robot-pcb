What the automation now does

KiCad is the design program. Its command-line tools let a script ask it to export files without clicking through menus. For this project, the script uses the existing KiCad 7.0.11 runtime, checks which source files it is reading, makes a working copy, refills the copper zones and runs a fresh design-rule check through KiCad's Python interface.

The workflow is set up and has run successfully. ERC (the schematic electrical-rule check), a fresh independent net comparison, an approved assembly BOM, corrected placements and a new JLC quote remain outstanding. The earlier v0.5 validation reported agreement across 126 multi-pin nets; this export run did not repeat that comparison.

What still stands between this and an order?

  1. Choose the actual switch, SW1. Its eight-hole footprint is provisional. We need an orderable part whose terminals and panel mounting fit, and whose DC switching rating covers the 33.6 V packs, load current and charging of the board's capacitors. A family datasheet alone does not settle the exact configuration.
  2. Resolve the Thor inductor, L1. The proposed ZE part has an open 30 V family-limit question during startup and a recommended land pattern that differs from the board. This needs a qualified part or manufacturer evidence plus a matching footprint.
  3. Check one-pack operation and correct the bead selection. If one BMS opens, the other pack and its entire path must carry the robot. Review copper, returns, connectors, switch contacts and fuses against that load. FB1/FB2 still contain the wrong C1015 supplier code in the generator; the candidate replacement has not been selected or qualified.
  4. Prepare and inspect a fresh assembly quote. Once the design changes are settled, regenerate from the reviewed sources, reconcile the BOM and placements, and inspect the actual Gerbers and JLC placement preview. The existing cart and older Gerber ZIP describe earlier hardware.

Why a clean check does not settle everything: the design can connect every pad correctly while specifying an inductor with the wrong land pattern or a bead with the wrong supplier code. Those are different questions. The useful learning goal is to distinguish “the drawing connects correctly,” “the selected part fits and is rated for this job,” and “the built board behaves correctly under load.”

If you want to rerun the review

From the project folder, choose a new output directory:

bash source/fabrication/run_v05_review.sh review-export --output /tmp/robot-pdb-next-review

The detailed instructions are in docs/FAB_AUTOMATION.md. The tested project outputs are in outputs/fabrication-v05-review/. The script keeps the design sources unchanged and refuses an output folder that already contains files.
